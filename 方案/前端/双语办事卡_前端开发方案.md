# 双语办事卡｜iPhone 前端开发方案

**目标设备：** iOS 18 或以上的 iPhone。使用 SwiftUI 和 `NavigationStack`，首版支持英文和简体中文。

**设计目标：** 让第一次到中文校园服务台办事的国际学生，在离开柜台前就能确认「带什么、去哪、最晚几点」，隔天还能打开同一个事项继续办。App 的核心不是翻译聊天，而是一张可以递给对方看、确认后带走的双语办事卡。

本方案沿用[团队开发方案](../../双语办事卡_开发方案.md)的业务流程。语音、联网翻译与关系图谱按[最新后端开发方案](../后端/双语办事卡_后端开发方案.md)对接；第一阶段仍用键盘完成确认、保存和离线重开。

## 一、页面与主流程

**我的事项 → 准备问路卡 → 出示问句 → 记录与核对答复 → 回到同一事项。** 在路上问路和在柜台确认要求，可以重复走「出示 → 记录 → 核对」；每轮交流都归入同一个事项。

| 页面 | 交互设计 |
| --- | --- |
| 我的事项 `TaskListView` | 按「进行中」「已办结」分组，各组按最近更新排序。每条显示事项名和下一条已确认但未完成的行动；没有可做的行动时提示需要追问哪个字段。首次启动显示空列表，演示样例通过单独入口添加。 |
| 准备问路卡 `PrepareCardView` | 输入办事目的，选择想问的地点、材料或时间。先给学生看英文，再预览给对方看的中文。首版可用校对过的问句模板；自由输入保留原文，允许手动补译文。 |
| 给对方看 `ShowCardView` | 全屏显示问句或已确认要求，默认大字中文、下方英文，支持交换主次。仅展示当前要沟通的内容，不显示其他事项、历史或编辑控件。 |
| 记录与核对 `ReviewReplyView` | 首版先支持打字。接入语音后，学生和工作人员分别使用标注「英语」「普通话」的按钮：按住说话，松手核对；可回听本轮录音并修正转写。原话和可编辑字段上下排列，中英相邻。未提及的字段标为「待问」，可追问或先保存已有内容。 |
| 事项详情 `TaskDetailView` | 先显示当前有效的双语清单，再显示可展开的交流历史。可勾选行动、追加答复、办结或重新打开。后续从清单字段点「查看依据」，按来源打开相应答复；关系图谱作为详情页的补充入口。 |

## 二、核心交互：一起核对答复

下面是英文界面的文字线框。工作人员说「周五四点前」，随后当面把时间改成三点半。

```text
‹ Submit enrollment documents

Review the reply

Original reply
“周五四点前，把护照复印件交到一楼服务台。”

Bring                                  Edit
护照复印件
A photocopy of your passport

Drop off at                            Edit
一楼服务台
Service desk, Level 1

Deadline                               Edit
周五下午三点半前
By 3:30 p.m. on Friday
Edited during review

[ Confirm and save ]
```

- **更正不改历史。** 同一轮把 16:00 改为 15:30 时，两种语言用同一个确认值生成，并标明「用户核对时修改」；历史保留最初的「四点前」。若下一轮才更正，新增一轮答复、沿用原行动 ID，只更新截止时间及其来源，不改材料和地点的来源。只说「周五」时保留原表述，不替用户推算日期。
- **缺失不等于不需要。** 只问到了地点时，材料仍标为「待问」，不自动填成「无需材料」。从待问项进入追问卡，结束后回到同一事项。
- **保存需要明确反馈。** 提交时禁用重复点击，直到成功才提示「已保存」并返回详情。保存失败保留当前草稿，提示用户重试；重试继续用同一草稿 ID。

## 三、视觉、排版与语言

**视觉方向：校园服务台的确认票据。** 核对和详情页用一张连续的白底票据承载信息，分隔线只用来区分字段。把最醒目的字号留给需要递给别人看的问句，而不是页面标题。文字统一左对齐，中英上下排列，避免窄屏上两列挤压。

| 用途 | 色值 |
| --- | --- |
| 页面底色 | `#F5F8FC` |
| 票面 | `#FFFFFF` |
| 正文 | `#162D4B` |
| 主要操作 | `#245694` |
| 字段分隔线 | `#D5DFEC` |
| 待问文字 | `#78541B` |

使用 iOS 系统字体（英文 SF、中文苹方）；正文以 17 pt 为基准，出示问句以 38 pt 为基准。支持动态字体、换行和滚动，状态有文字而不只靠颜色，控件有 VoiceOver 标签，「待问」和「已办结」能被读出。

三种语言设置独立，不用同一个开关：

| 设置 | 默认和切换行为 |
| --- | --- |
| 界面语言 | 全新安装默认英文，即使系统为中文。首页和事项内都能切换；当前页面、编辑草稿和勾选状态保留。用 `Localizable.xcstrings` 管理文案和辅助功能标签，用 `@AppStorage` 保存偏好，在根视图注入对应 `Locale`。 |
| 出示卡的语言顺序 | 中文在上、英文在下，可切换；不改变界面语言和卡片内容。 |
| 录音识别语言 | 学生输入默认英语，工作人员答复默认普通话。录音前单独选择；不受界面语言影响。 |

## 四、前后端分工与联调

前端负责页面、导航、草稿、交互状态和来源展示。数据侧负责 SwiftData 持久化、WhisperKit 本地识别、Python 翻译服务及图谱数据。第一阶段不依赖网络，用「补交入学材料」固定样例做页面，优先联调 `confirmReply` 和 `loadTask`。

| 任务 | 前端与接口约定 |
| --- | --- |
| 创建与读取 | 用 `createTask` 拿到事项 ID；用 `listTasks` 和 `loadTask` 加载列表、按时间排序的答复、当前清单及字段来源。在同一事项下追加后续交流。 |
| 确认保存 | `confirmReply` 接收事项 ID、草稿 ID、原文、译文和核对后的行动字段。最初输入或转写与核对后的原文分开保留；字段记录来源答复和是否手改。编辑已有行动沿用原 ID，新增要求单独追加。 |
| 勾选、办结与重开 | `setItemDone` 和 `setTaskCompleted` 成功后刷新当前事项和列表；不同事项的草稿、清单和进度独立。 |
| 本地识别 | WhisperKit 返回转写和本地录音引用。松手后显示「正在转写」，结果进入可编辑原文。模型未就绪、识别失败或拒绝麦克风权限时，可直接打字走同一流程。 |
| 联网翻译 | 用户核对原文后再发起 `POST /translate`，仅发送已核对的文字及源、目标语言。录音和办事记录留在手机，API 密钥留在服务端。断网或超时保留本地草稿，支持手填译文或重试；译文核对后才保存。 |
| 防止旧结果覆盖 | 发起识别或翻译时记录事项 ID、草稿 ID、版本号。只有三项都匹配才更新当前草稿；旧结果不能覆盖刚改的字段或另一个事项。 |
| 字段来源与关系图谱 | `ForceGraphView` 按稳定 ID 展示事项、答复和行动节点，点击节点打开详情。连线是无向的，关系以保存的字段来源为准；不看图也能从清单逐项打开依据，语音答复可回听、键入答复可读原文。 |

## 五、实现顺序与验收

1. **用键盘跑通保存和重开。** 用固定双语样例完成五个主流程页面，联调 SwiftData 的保存与读取，同时验证多事项隔离和切换语言不丢草稿。
2. **接入 WhisperKit 离线转写。** 在演示机准备模型资源；验证中英文按住录音、松手核对、回听和编辑。麦克风不可用时仍可打字。
3. **接入联网双向翻译。** 测试英文问句和中文答复进入同一核对流程。验证断网／超时可手填或重试，旧结果不会覆盖已改字段。
4. **接入字段来源和图谱入口。** 先保证清单里的「查看依据」指向正确答复，再增加图谱导航。已保存的双语卡、内置问句及保存的来源可离线查看。

| 验收场景 | 通过条件 |
| --- | --- |
| 补交入学材料 | 问路和柜台答复都在同一事项。把 16:00 改成 15:30；保存、退出并断网重开后，中英清单都是 15:30，历史仍是「四点前」，该字段标注「用户核对时修改」。 |
| 领取遗失水杯 | 第二个事项只填地点时，材料显示「待问」。追问、补填、勾选、办结后可重开，且不影响入学事项。 |
| 自由输入 | 可输入预设之外的问题，例如「如何借投影转接线」；即使没有自动译文，也能手动核对并保存。 |
| 中途切换语言 | 中文系统全新安装时界面为英文；录入半条答复切换为中文，页面和草稿不变，重启记住选择。 |
| 保存失败和旧结果 | 模拟保存失败，重试后只生成一轮答复；延迟返回的 16:00 译文不能覆盖刚手改的 15:30。 |
| 离线转写与联网翻译 | 模型就绪后在飞行模式录入中英文，能回听并编辑；断网翻译保留草稿，联网后可重试。关闭麦克风权限时，键盘仍能完成整个流程。 |
| 两轮答复的字段来源 | 第一轮给出地点和 16:00，第二轮改为 15:30。断网重开后，截止时间指向第二轮，地点指向第一轮；清单和图谱都能进入对应答复。 |
| 无障碍 | 最大字号仍可阅读并操作；用 VoiceOver 可按字段读出中英内容，不必靠拖动图谱来查看来源。 |

Windows 可用于编写 Swift 源码、文案和样例；iOS 界面的编译、预览和真机验收需在 macOS 上使用 Xcode。
