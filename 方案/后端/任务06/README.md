# 任务 06 · 从截止时间和地点找回原话

同一项「交护照复印件」有两个来源。周五的截止时间改到 15:30，要回听第二轮；地点仍是一楼服务台，要显示第一轮键入的整句。可以先用两组 JSON 数据做界面预览，再在 iPhone 录入真实答复。预览里的 ID 是样例代号，录音路径是占位值。[界面预览数据](field-sources.json)

## 在 iPhone 录入两轮

1. 使用装有本地语音模型的 iOS 18+ 演示 App，iPhone 和运行任务 04 翻译服务的电脑连同一局域网。在核对页配置电脑地址，例如 `http://192.168.1.23:8000`。下面两轮先联网翻译并保存。
2. 选「新建事项 → 自定义事项」，中文名称填「补交材料」，中文问句填「护照复印件该何时交到哪里？」。勾选「地点」「要带什么」「时间要求」，点「创建事项」。
3. **第一轮，键入。** 点「记录答复」，选「办事要求」和「简体中文」。键入“周五四点前，把护照复印件交到一楼服务台”。点「核对答复 → 翻译成英文」。在字段中填地点「一楼服务台」、材料「护照复印件」，打开「设置明确时间」，选周五 16:00，保留「最晚在此时间前到达」，点「确认并保存」。此轮没有录音。
4. **第二轮，真人录音。** 回到同一事项，在已有的「时间要求」行点「… → 修正要求」。按住「按住说中文」，说“改到下午三点半，地点不变”。首次授权若中断，授权后重新按住录制。松手后等转写结束，点「回听本轮录音」核对内容，点「翻译成英文」。将继承的周五 16:00 改为 **15:30**，保留周五和截止属性，再点「确认并保存」。这次只修正时间。
5. 先在「交流记录」检查两轮的顺序、第一轮整句和第二轮回听。界面接好图谱后，打开同一事项的图谱，点行动「交护照复印件」，按下表逐个点字段。图中预期共 4 个节点（1 事项、2 答复、1 行动）。
6. **离线重开。** 开启飞行模式并确认 Wi-Fi 已关闭，从 App 切换器划掉 App，重新打开「补交材料」。再点一次截止时间和地点。听到同一段第二轮录音，并读到同一句第一轮原话才算通过。在已有「交流记录」中回听可单独验证本地录音，图谱点按需在接好图谱的版本验收。

| 行动字段 | 第二轮保存后的值 | 点开后的预期 |
| --- | --- | --- |
| 截止时间 | 周五 15:30 前 | 第二轮。显示初始转写，能听见“改到下午三点半，地点不变”。 |
| 地点 | 一楼服务台 | 第一轮。显示“周五四点前，把护照复印件交到一楼服务台”。 |
| 材料 | 护照复印件 | 第一轮。同一句键入原话。 |

## 对照 · 只在同一轮手改时间

另建事项「补交材料（同轮手改）」，重复第一轮输入。核对页先设周五 16:00，然后在**第一次保存前**将时间改为 15:30，保留原句“四点前”。只保存一次。预览和接入后的期望是 1 个事项、1 轮答复、1 个行动；截止时间仍指向这一轮，同时显示原话和“用户核对时修改”。这个用例的截止时间 `userEdited = true`，地点和材料为 `false`。前一个两轮样例的三个字段均为 `false`。

## 数据接入位置

核对基线为 `main@6fabe29`。现有事项详情用 `@Query` 读取同一 `taskID` 下的字段行和答复，分别按 `createdAt` 和 `confirmedAt` 排序。任务单里的 `loadTask(taskID)` 是要接入的读取接口。当前 App 的核查入口是「事项详情 → 交流记录」，图谱入口与点按由界面队友接入。[事项详情与查询](../../../CampusCards/CampusCards/Features/TaskDetailView.swift)

| 交给界面的数据 | 从当前模型读取 |
| --- | --- |
| 事项节点 | `CampusTask.id` 和本地化标题。 |
| 答复节点 | `ConversationTurn.id` 是稳定 ID。初始原话取 `originalText`，核对原文（样例的 `confirmedText`）取 `original`，译文取 `translation`。旧记录若缺少 `originalText`，可以显示 `original` 并标明是核对原文。 |
| 行动字段与跳转 | 每条 `ActionItem` 存一个字段。类型取 `kind`，显示值取 `text` 或结构化 `time`。用选中字段的 `sourceTurnID` 在该事项的答复中按 ID 定位。更正时间时保留时间行的 `id`，只更新这行的值和来源。 |
| 缺少字段 | 显示「待问」，没有来源可点。 |
| 回听 | 读取目标答复的 `recordingRef`。键入轮为 `nil`，录音轮由设备生成 `Recordings/<独立 UUID>.wav`，由 `ReplyRecordingFiles.url(for:)` 在本机 Application Support 下解析。沿用 `RecordingPlaybackButton(recordingRef:)`，实际文件名由录音模块分配。 |

[答复模型](../../../CampusCards/CampusCards/Models/ConversationTurn.swift) · [行动字段](../../../CampusCards/CampusCards/Models/ActionItem.swift) · [保存与更正](../../../CampusCards/CampusCards/Persistence/TaskStore.swift) · [录音与回听](../../../CampusCards/CampusCards/Features/ReplyAudio.swift)

这两组预览各显式定义一个行动，把材料、地点和截止时间列在同一节点下。事项连到各轮答复和行动，行动按字段来源连到对应答复。地点和材料共用一条指向第一轮的图线时，仍须保留各自的字段依据。真实数据中每个字段已有稳定 ID；`main` 还缺少跨字段的行动分组 ID 和字段级 `userEdited`。多行动场景的分组和手改标记需要数据层补齐，不能仅凭同一事项、转写差异或轮次先后推断。

## 验证范围

本次核对了上述 Swift 存取代码，以及两组预览的字段指向和录音路径格式。演示机上的真人录音、原生图谱点按、飞行模式彻底退出后的回跳与回听、同轮手改标记都待测。验收时请分别记录设备与 App 版本、所点字段、看到的初始原话和实际听到的内容。
