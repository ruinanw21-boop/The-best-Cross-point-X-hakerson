# 双语办事卡｜后端开发方案

开发顺序是 **SwiftData 保存和重开 → WhisperKit 本地识别 → 第三方 API 中英互译 → ForceGraph 关系图谱**。前三步共用一张核对页。录音和办事记录保存在 iPhone，翻译时只把用户核对过的文字和语言方向发给服务端。

## 1. 用固定样例打通保存和重开

先和界面队友拿到 Xcode 工程、App target 名和演示机型号。团队原型面向 iOS 18 及以上的 iPhone。Windows 上可以准备样例、编写 Python 翻译服务，Swift 集成和真机验收在队友的 Mac 上进行。

**第一项交付**是在 iPhone 上新建「补交材料」，手工输入双语样例。柜台原话是“周五四点前，把护照复印件交到一楼服务台”。用户在核对页把截止时间改为 15:30，确认并退出。断网重开后，清单显示“周五 15:30 前 / By 3:30 p.m. on Friday”，历史里仍能看到“四点前”，并能看出时间由用户核对时修改。

直接使用 Apple 的 **SwiftData**，在 App target 中配置写入磁盘的 `ModelContainer`，通过 `ModelContext` 保存和读取以下记录。[Apple 持久化示例](https://developer.apple.com/documentation/swiftdata/preserving-your-apps-model-data-across-launches)

| 记录 | 要保存的内容 |
| --- | --- |
| `CampusTask` 事项 | 稳定 ID、办事目的、双语问句、进行中／已办结、创建与更新时间。 |
| `ConversationTurn` 一轮答复 | 所属事项、草稿 ID、顺序、说话人、语言、最初输入或转写、核对后的原文与译文。语音答复可另存本地录音引用。 |
| `ActionItem` 行动项 | 稳定 ID、所属事项、当前双语要求、材料、地点、截止时间和完成状态。每次确认字段时，记下字段名、确认值、来源答复和是否由用户手改，供图谱回溯。 |

工作人员在**下一轮**更正时间时，新增一轮答复，沿用原行动 ID，只更新截止时间及其依据。材料和地点仍可追到最初的答复。额外要求带学生证时新增行动。没提到的字段留空，界面显示「待问」。只听到“周五”就保留原文，具体日期由用户确认。

| 界面操作 | Swift 接口约定 |
| --- | --- |
| 新建、打开和列出事项 | `createTask` 返回事项 ID。`listTasks` 按状态和最近更新时间展示，`loadTask` 返回该事项的有序答复、当前清单和来源。 |
| 确认保存 | `confirmReply` 接收事项 ID、草稿 ID、原文与译文及核对后的行动字段，一次提交答复、字段变更和事项更新时间。 |
| 勾选材料或办结 | `setItemDone` 更新单个行动，`setTaskCompleted` 支持办结和重新打开。 |

每轮新草稿生成一个 ID，重试时复用。按事项和草稿 ID 查重，同一草稿串行写入。提交成功才提示「已保存」，失败时撤销本次写入并保留草稿。

## 2. 在 iPhone 上用 WhisperKit 离线识别

**直接接入 WhisperKit 的 Swift 包。** 在 Xcode 里添加 Argmax 的包，为 App target 选择 `WhisperKit`。按 v1.1.1 的接口接入，提前在演示机准备多语种 `openai_whisper-base` 和分词资源（tokenizer）。中英文按钮分别指定识别语言，两边都执行转写。WhisperAX 是较早版本的完整示例，可参考它的录音交互。[v1.1.1 转写示例](https://github.com/argmaxinc/argmax-oss-swift/blob/v1.1.1/README.md#whisperkit) · [多语模型](https://huggingface.co/argmaxinc/whisperkit-coreml/tree/main/openai_whisper-base) · [WhisperAX 示例工程](https://github.com/argmaxinc/argmax-oss-swift/tree/v0.17.0/Examples/WhisperAX)

界面队友负责「按住说话，松手核对」。Swift 侧每轮生成一段本地录音，返回草稿 ID、转写文字和录音引用。核对页同时提供回听和文字修改。键盘输入也进入同一核对页。断网仍可转写，拒绝麦克风权限时仍可打字。

**语音界面只借鉴两个项目的设计。** 答复详情参考 CapsWriter-Offline，点击转写旁的时间就能回听原录音。输入页参考 Swift Universal Translator，学生和柜台人员各用一个标有自己语言的麦克风按钮。[CapsWriter 录音归档源码](https://github.com/HaujetZhao/CapsWriter-Offline/blob/master/core/client/diary/diary_writer.py) · [Swift Universal Translator](https://github.com/ZachNagengast/swift-universal-translator)

若楼名、窗口名或中英混说在真机上反复出错，用同一组录音比较 **sherpa-onnx + SenseVoiceSmall**。记录关键字段认错几处、松手到显示原文用了多久，再决定是否替换。它是备选识别引擎。[sherpa-onnx iOS 工程](https://github.com/k2-fsa/sherpa-onnx/tree/master/ios-swiftui) · [SenseVoice Swift 示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/swift-api-examples/decode-file-sense-voice-with-hr.swift)

## 3. 用 Python 后端调用第三方翻译

**直接接入阿里云 DashScope Python SDK**，由后端调用百炼的 `qwen-mt-flash`。团队实现一个 `POST /translate` 接口。iPhone 发核对后的文字、源语言和目标语言，接口返回译文。API 密钥只放后端环境变量。校园部门和窗口有核实过的英文名时，通过 `translation_options.terms` 传入对应词条。[DashScope SDK](https://github.com/dashscope/dashscope-sdk-python) · [Qwen-MT 双向翻译与术语示例](https://help.aliyun.com/zh/model-studio/machine-translation)

先用键入的 “Which desk should I go to?” 调通英译中，再把第 2 步的中文口述接到同一接口测中译英。客户端发起每次识别或翻译时记住事项 ID、草稿 ID、版本号。用户修改或切换草稿后，只接纳与当前三项都匹配的结果。超时或断网时把原文留作本地待翻译草稿，恢复后可重试。译文进入核对页，用户确认后才调用 `confirmReply`。

## 4. 用 ForceGraph 展示关系并跳回原话

**直接接入 ForceGraph 的 Swift 包。** iPhone 的 Swift 数据层通过 `loadTask` 读取当前事项，把 SwiftData 中的事项、答复、行动映射成节点，把它们的关联映射成连线。每个节点带稳定 ID、类型和显示标题。界面队友用 `ForceGraphView` 绘图，按节点 ID 打开详情。该组件显示无向连线，“包含”“依据”“更正”等含义以本地记录为准。[ForceGraph 接入与点按示例](https://github.com/ianleon/ForceGraph)

用两轮柜台答复联调。第一轮说“周五四点前交到一楼服务台”，第二轮说“改到下午三点半，地点不变”。图上有一个事项、两轮答复和一条待办。点待办里的「截止时间」打开第二轮，点「地点」打开第一轮。语音答复可以回听该轮录音，键入的答复可以查看原文。只有一轮、由用户手改时间时，详情标明“用户核对时修改”，并展示当时那一轮原话。

**Obsidian 用作图谱交互参考。** 如果团队后续决定导出资料，再为每个事项生成 Markdown，并把答复链接到随附录音。需要在 Obsidian 里点时间码回听时，可让使用者安装 Audio Timestamp Player，按它的格式导出录音标识和起始秒数。[Obsidian 图谱说明](https://obsidian.md/help/plugins/graph) · [Audio Timestamp Player 格式示例](https://github.com/ITNQ18/obsidian-audio-timestamp-player/blob/main/README.zh-CN.md)

LangExtract 可借鉴的一点是点开字段时高亮对应原文。第一版用用户确认的字段和来源答复生成图谱。若以后要自动从原话提取材料、地点和时间，再评估这个 Python 项目。[LangExtract 示例](https://github.com/google/langextract)

## 5. 演示机验收

- [ ] **本地保存**　完成第 1 步手工纠正样例，断网重开，双语清单一致且原话可追溯。连续点两次确认只有一轮记录。模拟保存失败后重试，草稿仍在且只写入一次。
- [ ] **多事项和状态**　给「领取水杯」只填地点，材料显示「待问」。补填、勾选、办结、重开后，「补交材料」的记录和进度保持正确。
- [ ] **离线识别**　模型和分词资源就绪后，开启飞行模式，完全退出并重开 App。分别口述中英文短句，能回听、修改转写并留下草稿。拒绝麦克风权限后还可键入。
- [ ] **双向翻译**　联网后用英文问路、用中文回答，核对后保存并重开。发起 16:00 的翻译后改成 15:30 并重译，旧结果晚到时仍保留 15:30。
- [ ] **关系追溯**　按第 4 步的两轮样例断网重开，截止时间和地点分别指向正确答复。点语音来源可回听，点键入来源可读原文。
