# 双语办事卡｜后端开发方案

你的工作分两阶段。**第一阶段，保存和读取用户核对后的结果。第二阶段，完成语音转文字和中英双向翻译。** 界面队友负责输入、展示和核对页面，调用你提供的 Swift 方法。

**第一项交付**：在 iPhone 上新建「补交材料」，键入柜台答复，把截止时间从 16:00 改成 15:30，点击确认。退出并重新打开 App，清单里的中英文都是 15:30，历史里还能看到最初的「四点前」。

## 1. 先和队友对齐

- 找负责 iOS 工程的队友拿到 Xcode 工程、App target 名和可联调的 Mac。你可以在 Windows 上先定接口、准备样例，再用队友的 Mac 编译，并通过 Xcode 安装到演示 iPhone。
- 给界面队友一组固定样例：事项「补交材料」，原话「周五四点前，把护照复印件交到一楼服务台」，确认结果「周五三点半前／By 3:30 p.m. on Friday」。这样双方可以同时开工。
- 第一次联调由界面传入手工准备的原话、译文和已确认字段。第二阶段由你提供真实转写和翻译，返回结果时带上事项 ID、草稿 ID 和版本号。两阶段共用同一个确认保存接口。

## 2. 要保存的三类数据

| 模型 | 记录什么 | 例子 |
| --- | --- | --- |
| `CampusTask` 事项 | 唯一 ID、办事目的、双语问句、进行中／已办结、创建与更新时间 | 「补交材料」和「领取水杯」是两个独立事项 |
| `ConversationTurn` 一轮答复 | 所属事项、草稿 ID、答复顺序、说话人、语言、原话与译文 | 第一轮问路，第二轮柜台答复「周五四点前」 |
| `ActionItem` 行动项 | 所属事项、来源答复、双语要求、材料／地点／截止时间、完成状态 | 「带护照复印件，周五三点半前交到一楼服务台」 |

一件事可以有多轮答复，一轮可以提出多个行动。更正截止时间时沿用原行动的 ID。工作人员额外要求带学生证时，新增一项。没提到的字段留空，由界面显示「待问」。只说「周五」就保留原文，等用户确认具体日期后再记录日期。

## 3. 给界面队友的接口

下表是第一阶段的数据接口。建议优先联调 `confirmReply` 和 `loadTask`，分别对应核对页的「确认保存」和详情页的「重新打开」。

| 页面要做什么 | 建议接口 | 返回结果 |
| --- | --- | --- |
| 新建一件事 | `createTask(目的, 问句)` | 新事项 ID，供后续问答使用 |
| 打开首页或详情 | `listTasks(状态)`、`loadTask(事项ID)` | 首页按最近更新排序。详情包含该事项的有序问答、当前清单和进度 |
| 确认一轮答复 | `confirmReply(事项ID, 草稿ID, 原话, 译文, 已确认行动)` | 一次保存答复和关联行动，返回已保存的答复 ID。出现错误时保留草稿供重试 |
| 勾选材料、办结或重新打开 | `setItemDone(事项ID, 行动ID, 是否完成)`、`setTaskCompleted(事项ID, 是否办结)` | 重新进入详情或列表时看到最新状态 |

**保存约定。** 打开一轮新草稿时生成草稿 ID，重试时复用。写入时按事项和草稿 ID 查重，串行处理同一草稿，把答复、行动项和事项更新时间一起提交。写入成功后才提示「已保存」。失败时撤销本次写入，保留输入。切换事项或修改字段后，核对页只接收与当前事项、草稿、版本都匹配的翻译结果。

## 4. 按这个顺序开发

1. **先打通保存和重开。** 在团队 App target 下建立三个模型，接入使用磁盘存储的 `ModelContainer`。先做新建、读取、确认三个操作，用固定样例和键盘在真机走完第一项交付。SwiftData 用 `ModelContext` 读取和保存数据。[Apple 持久化示例](https://developer.apple.com/documentation/swiftdata/preserving-your-apps-model-data-across-launches) · [ModelContext 文档](https://developer.apple.com/documentation/swiftdata/modelcontext)
2. **再接页面和状态。** 把接口接到事项列表、详情和核对页，完成勾选、办结和重新打开。加入「领取水杯」作为第二件事，检查每次修改只落在选中的事项里。
3. **第二阶段做语音和翻译。** 第一阶段通过保存与重开的验收后，用 Speech 将录音转成可编辑的文字，用 Apple Translation 支持英译中和中译英。键盘输入直接进入翻译，语音输入先由用户核对转写再翻译。把原文和候选译文交给核对页，用户确认后复用第一阶段的保存接口。

## 5. 交付前在演示 iPhone 上验收

**第一阶段 · 本地保存和读取**

- [ ] **纠正与重开**：保存 15:30，完全退出 App，再断网打开。中英文清单都是 15:30，原话仍是 16:00。
- [ ] **重复与重试**：同一草稿连点两次确认，只有一轮记录。模拟一次保存失败并重试，原输入可见，最终只留一份完整结果。
- [ ] **多事项与待问**：给「领取水杯」只填地点，材料显示「待问」。追问、补填、勾选、办结并重新打开后，「补交材料」的记录和进度保持正确。

**第二阶段 · 语音转文字和中英翻译**

- [ ] 英文键入“Which desk should I go to?”，得到中文问句。用普通话口述柜台答复，能修改转写、查看英文译文，并在确认后保存。同一事项重开后可读取双方确认的内容。
- [ ] 关闭麦克风权限，仍能打字、翻译和保存。
- [ ] 发起包含 16:00 的翻译，再手改成 15:30。较早的结果最后返回时，旧时间不会覆盖当前草稿和已确认结果。
